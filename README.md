# FBBC Matthews — Sequenced Funnel (v2)

Restructure of the single-page site into the 5-page funnel:

```
/            VSL page (indexed) — pre-headline, headline, video, ONE CTA, trust strip
/plan        Full sales letter (indexed) — every CTA → /apply
/apply       Quiz application (noindex) — 1 question/screen, contact at step 2
/book        GHL calendar embed (noindex) — prefilled, GHL owns availability
/confirmed   Fires CallBooked (noindex) — testimonials, expectations, 90-Day Promise
/resources   SEO section (own light template) — location pages, comparisons, FAQ articles
```

One room, one door: funnel pages have no nav and legal-only footers. All approved
sales copy was moved verbatim — do not rewrite it, and **do not edit the quiz
question wording** (Coach Nate's call framework Phase 2A reads answers back verbatim).

## GHL wiring (progressive capture)

The quiz posts to `/api/ghl`, which forwards server-side to `GHL_WEBHOOK_URL`:

1. **Step 2 complete** → payload with `tags: ["application-started"]` + contact + step-1 goal
   → your existing **abandonment workflow** fires on partials.
2. **Final submit** → `tags: ["application-completed"]`, `remove_tags: ["application-started"]`,
   all answers → your **booking-reminder workflow** fires.

Map these JSON paths to your GHL custom fields (keys match the brief exactly):
`customField.goal`, `customField.how_long`, `customField.obstacle`, `customField.readiness_score`.
UTMs + click IDs arrive under `attribution.*` — map `utm_source/medium/campaign/content/term`
to contact fields so ad→booked-call attribution is visible in GHL.

**Calendar:** in GHL, set the Transformation Call calendar's post-booking redirect
("Thank You URL") to `https://<your-domain>/confirmed` — that's what fires the
CallBooked/Schedule conversion. The embed also listens for the widget's booked
postMessage as a fallback. Name/email/phone are prefilled via URL params from the quiz.

## Tracking

| Event | Meta | GA4 | Fires when |
|---|---|---|---|
| VSLPlay | custom | event | first play tap |
| VSLProgress25/50/75/100 | custom | event | watch-depth quartiles (retargeting cutdowns: 25%+ → the :45 "secret" cutdown) |
| ApplyStarted | custom | event | quiz step 2 complete (mirror of GHL partial tag) |
| ApplyCompleted | **Lead** | event | final quiz submit |
| CallBooked | **Schedule** | event | /confirmed load |

UTMs persist via localStorage + query passthrough on every CTA, and ride into the webhook payload.

## A/B tests (feature-flagged)

Sticky 50/50 cookies assigned in `middleware.ts`; force a winner sitewide via env
(`NEXT_PUBLIC_AB_HEADLINE|AB_Q1|AB_SKIP_PLAN` = `a`|`b`) — no code change to ship a winner.

1. **headline** — VSL page: current headline vs. mirror-moment-first (per VSL deployment notes)
2. **q1** — /apply step 1: current vs. "What would change in your life if this finally worked?"
3. **skipPlan** — visitors with recorded watch depth ≥75%: VSL CTA → /plan vs. straight to /apply

Read the variant cookies in your analytics (they're also sent as `ab_q1_variant` in the webhook).

## v6 — quiz removed (friction test)

Flow is now `/` → `/book` → `/confirmed`. `/apply` 301s to `/book`; `components/QuizForm.tsx`
stays in the repo dormant. To restore the quiz: revert `app/apply/page.tsx` to render QuizForm
and point CTAs back to `/apply`. NOTE: with no quiz, the GHL webhook (application-started/
completed tags, goal/how_long/obstacle/readiness_score fields) receives nothing — the call
framework's Phase 2 (reading answers back) has no inputs, and lead capture happens entirely in
the GHL calendar form. Watch show rates and call quality; that data decides if the quiz returns.
